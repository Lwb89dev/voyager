# Legacy Flutter data migration

## Identity and release boundary

Voyager keeps application ID `com.voyager.voyager`; the native version code is 7, above the Flutter baseline's 6. Existing signing configuration remains external to the repository. A signed update from a previously installed legacy APK has not yet been validated and remains a release blocker.

## Legacy formats

The Flutter application owns `app_flutter/settings.hive` below its private data directory. It is a Hive 2.2.3 box whose frames are protected with AES-256-CBC and CRC32. The 32-byte key is Base64-encoded under `hive_settings_key` in Flutter Secure Storage.

`FlutterSecureStorageReader` reads the existing Android Keystore keys without creating, replacing or deleting them. It supports the two default on-disk combinations relevant to Voyager installations:

- RSA-PKCS1-wrapped AES with AES-CBC values, used by older secure-storage releases.
- RSA-OAEP-wrapped AES with AES-GCM values, used by current secure-storage releases.

Biometric key variants and the older Tink EncryptedSharedPreferences format are not currently decoded. They fail the import rather than resetting the data. A real signed-install test must establish whether any supported installation still requires another format.

The native reader does not initialize Flutter or include a Flutter engine in the APK.

## Native import sequence

The first native startup runs the import on an IO coroutine before displaying Roadstr or constructing Voyager plugins:

1. Detect and read the legacy box without modifying it.
2. Validate frame lengths, checksums, encryption, value types and preference shapes.
3. Map supported values into a versioned snapshot and record unsupported categories.
4. Stage the snapshot and write native stores. Every write is idempotent.
5. Reopen each native store and compare it with the snapshot.
6. Write the completion marker last, in `voyager_native_migration`.

A crash before the marker leaves the import eligible for a complete retry. Legacy files are never deleted, truncated, compacted or re-encrypted by this process. A read, write or verification failure displays retry and an explicit continue-without-importing choice. Unsupported categories are displayed after a successful import and also recorded with the marker.

## Version 1 scope

Version 1 imports data that the native runtime can already consume and verify:

- The active Navidrome or Jellyfin configuration, including credentials, into the Keystore-backed music store. Navidrome keeps the legacy application's precedence when both are configured.
- Podcast subscriptions.
- Equalizer enablement, preset and custom gains into the persistent native equalizer store.
- Night dimming and volume-key remapping.
- Legacy onboarding completion.

The following are explicitly reported and left only in the original files for a later migration version:

- Roadstr's shared settings, saved places, history, reports, identity, relay/wallet/sync state and other profile data (`roadstr:profile_pending`).
- A secondary configured music backend, because the current native music store holds one active configuration (`music:secondary_backend`).
- Music folder filters, model paths, light-theme/chrome preferences and unknown `voyager_` keys.
- Feed/model/package files and active playback queues. These need separate path/format validation; raw encrypted storage is never copied blindly.

An imported legacy Nostr private key is outside version 1 and is never written to Voyager's music or preferences stores. The future Roadstr profile import must apply the logged-out-with-notice policy for the deprecated pasted-`nsec` login.

## Automated evidence

The test fixture at `android/app/src/test/resources/legacy/settings.hive` was generated by the real Hive 2.2.3 implementation. JVM tests cover primitive/list/map decoding, repeated writes, deleted frames, wrong keys, corrupted frames, mapping of actual Voyager values, unsupported-data reporting, completion-marker ordering, idempotence, retry after a failed commit and failed verification.

## Still unverified

- RSA unwrap and value decryption against Android Keystore on a physical device.
- Upgrade from a signed legacy Voyager APK with realistic credentials and subscriptions.
- Crash interruption at each native write boundary on device.
- Every legacy secure-storage variant that may exist in the installed base.
- Roadstr profile import and asset/package reuse.

These checks must not be inferred from the JVM fixture tests.
